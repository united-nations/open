# UN Transparency Portal — adversarial data integrity audit

## Technical summary

**The portal is not ready for an unqualified data-integrity sign-off.** The consolidated register contains 21 findings: eight high, twelve medium and one low, including explicitly identified source-basis and provenance limitations. The audit found material revenue omissions, financing-category misclassification, and unsupported UNINFO year/country attribution. The Secretariat Overview exactly reproduces the selected ARWO workbook, but faithful extraction does not establish a single consolidated accounting basis. Original-source checks also exposed budget-detail problems that aggregate total checks cannot detect.

This review covers the current working tree, including existing uncommitted changes, at commit `c7a103f`. It also compares the deployed preview. Findings about one version are not automatically findings about the other. Financial defects, source limitations and coverage gaps are distinguished throughout; issue amounts are not additive.

## Scope and financial definitions

The inventory contains 14 routes and 274 JSON files. It includes the directly accessible Field Missions route despite its hidden navigation entry, the new Functions view, contributor subroutes, sidebars, trends, and static UNINFO detail. CEB revenue is recognized revenue, Secretariat Overview is the ARWO expense reconstruction, PPB distinguishes proposed/approved/expenditure, peacekeeping uses July–June cycles, and UNINFO describes Cooperation Framework required/available/spent resources. These populations and measures cannot be naively summed or reconciled to one common total.

Primary evidence was followed upstream to current original CEB downloads and UNINFO responses, original ARWO Excel workbooks, original PPB PDF/DOCX tables, and published financial statements. Every ARWO raw expense row was checked. PDF/DOCX manual review is sampled and is recorded separately from exhaustive JSON arithmetic.

## Revenue errors survive internally consistent exports

PAHO's 2024 sidebar displays **Total funding $0**, although the original CEB revenue rows total **$1,195,033,314**. Searching PAHO in the Funding view returns no matching entity. IRMCT's 2023 exported revenue is **$1**, versus **$76,239,000** in both CEB rows and the independently visually inspected Table 2 of A/79/494. The detail-driven export loses known revenue when contributor detail is incomplete. Donor and entity exports agreeing with each other is therefore insufficient validation.

Historical residuals confuse unknown contributor identity with the Other financing instrument: UNICEF 2020 Other revenue is overstated **$1,997,096,902.15**, although its overall revenue total matches. Separately, the legacy `R02` core-funding code falls through to earmarked, misclassifying **$409,788,022.22 in 2018**. The contributor trend exporter then folds Other into earmarked again: for World Bank 2024, **$437,948,928** changes category between the annual view and the trend. Across named contributors that trend reclassification is **$1,312,409,027.34 in 2024**.

The default “All contributors” trend omits aggregated/unattributed rows: **$55,137,083,979.18** versus **$67,111,491,599.99** in annual donor JSON for 2024. This can be a valid restricted view, but its scope needs an explicit label.

## Positive chart areas must not determine signed financial totals

The 2024 contributor chart derives its headline from positive-net contributors: **$67,412,398,924.54**, compared with the signed dataset's **$67,111,491,599.99**. Its excess is **$300,907,324.55**. Legitimate negative corrections remain in JSON but cannot reduce the chart headline or appear as negative-net tiles. This is distinct from the missing PAHO revenue and should not be netted against it.

The chart below shows this one mechanism across all shipped contributor years with all funding enabled. The denominator for the retained excess-rate field is each year's signed donor total. It is not a comparison against a fully reconciled CEB system total. Funding-subset checks found the same mechanism in 119 of 180 year/filter combinations.

## UNINFO period and geography need explicit provenance

**Thirteen country exports carry unfiltered-period fallback values under a 2024 label.** The affected countries are COD, BHR, COM, DJI, ETH, JOR, MMR, NAM, PRY, RWA, SLE, SYR and UKR. Exposed values total **$8.855B required, $4.755B available and $525.607M spent**. Those amounts quantify affected content; corrected 2024 values are not known. The original COD 2024 query is empty while the query without a year filter is nonempty. The exporter drops the flag distinguishing the two. The code calls the fallback “all-time,” but the API default interval is undocumented; the narrower confirmed finding is that the 2024 attribution is unsupported.

**Twelve country files repeat two shared workspaces.** Nine Pacific countries receive identical workspace-wide metrics, and Brunei, Malaysia and Singapore receive the same three-country workspace totals. A shared workspace is not a verified allocation to each country. Summing the repeated copies would repeat **$702.116M spent** beyond one copy per workspace; the audit does not claim the global UNINFO headline performs that sum.

The source itself does not consistently obey Required ≥ Available ≥ Spent. Across country totals, SDGs, projects and framework nodes, 388 exported nodes violate that assumed ordering. Haiti project 135479 reports **$4,570,500 required** and **$50,262,036 available/spent**. Clipping the latter two bars to required makes an elevenfold difference look equal. Preserve reported values, expose source anomalies, and use a scale that represents them honestly.

Smaller findings: Goals methodology incorrectly denies using UNINFO despite its sidebar; 1,136 project-ID groups contain multiple agency rows, so project counts and React keys need correct grain; malformed Curaçao encoding drops **$834,112.63** of historical geographic expenditure; old CEB source URLs return 404. The recovered current geographic source has revised grain/allocations and remains a separate reconciliation gap.

## Secretariat arithmetic passes, with accounting and presentation qualifications

All **2,456 numeric ARWO rows** in the latest workbook reconcile to **1,681 exported entity × priority × funding intersections**, 2019–2025. The audited programme/peacekeeping trees reconstruct all seven Overview annual totals. Overlapping ARWO editions were compared directly: the 2020 total rises **$1,455,183** from the earliest edition because of an added UNCTAD row; other small changes include rounding and relabeling. The app matches the selected latest edition.

The Overview nevertheless drops negative-net entities from the treemap. For 2023, signed expense is **$14,791,811,849** but positive tiles total **$14,792,950,920**, an excess of **$1,139,071**. Compact formatting hides the total difference, and negative entities disappear from search.

UNEP illustrates a source-basis limitation. ARWO adds **$671,941,000** non-regular-budget residual to **$20,859,739** PPB-derived regular expense, giving **$692,800,739**. The original 2023 UNEP audited statement reports **$696,642,000**, with regular-budget expense **$24,701,000**. The **$3,841,261** difference is a mixed-basis construction, not a transcription error. The UI's Extrabudgetary label is preferable to calling this residual pure voluntary funding, but its assertion of consolidated elimination of internal transfers is not established by this reconstruction. A source-basis decision and explicit bridge are required before changing totals.

Primary-priority placement is disclosed in methodology: the treemap assigns whole entities to a primary priority, while source cells retain multiple priorities. It should not be mistaken for exact spending by priority. This is documented behavior rather than an undisclosed accounting defect.

## Budget controls require source-cell review as well as sum checks

Structural checks covered **45 budget JSON files and 18,189 nodes**, including legacy aliases and audited files. Root totals and IDs passed. Of **25,569 parent/funding-subset comparisons**, 217 exceed the independently chosen source-rounding bound; aliases and subsets repeat observations. These are reconciliation candidates, not 217 confirmed bugs. Printed controls must not automatically be replaced by sums of children.

Manual PDF checks covered Section 14 across all seven PPB editions and original DOCX table cells for each edition. Selected expenditure, approved, proposed and extrabudgetary totals matched. Original MINURSO pages also matched all three shipped peacekeeping cycles, with fiscal period and gross/in-kind distinctions checked.

For OLA Proposed 2022, the parent **$27,561,100** is present but four printed component amounts are missing from projected values. The original source table has an erroneous year header; surrounding tables support the intended 2022 figure. Recovering detail requires an evidenced source exception, not silently assigning values based on a guess. Further original-document reconciliation confirms a **$861,200 superseded Proposed 2025 section 24 control**: the app uses $241,071,400, while corrigendum Annex III explicitly prints $240,210,200. Its corrected child amounts are present. A lower programme subtotal discrepancy also exists in the corrigendum itself and must remain identified as a source inconsistency.

For Proposed 2024 section 33, a newly budgeted **$3,500,000 conferencing-infrastructure line** is absent from the expenditure-based hierarchy. The app correctly retains the $30,985,800 section control but exposes only $27,485,800 of detail. Both gaps are disclosed in the current browser sidebar; the confirmed issues concern a superseded control and missing known source detail, not a hidden subtraction from both headlines.

## Contribution schedules mostly reconcile; some citations identify the wrong column

Trust-fund spending checks reconcile **1,118 fund-years**, including all leaf and parent totals. Every exported contributor flow/destination reconciliation was checked. Regular-budget contributor checks cover **1,544 state-years**, and peacekeeping covers **772 state-cycles**. Internal totals and recorded payment-status/date logic pass. These are not independent verification of all payment statuses or all PDF source rows.

Manual original-source checks include 16 largest trust-fund expense/contributor samples across all eight years, three seeded random expense rows, two original 2017 Word tables, US assessment rows in all eight regular-budget circulars, and 11 assessment/credit rows in MINURSO circulars across three cycles. Selected amounts match, including negative credit/adjustment handling. The three random draws use seed 20260916 from the complete population of 1,118 fund-year expense facts; they are not a statistical certification. The eight largest expense checks plus three random expense checks cover 11/1,118 observations (0.98%) and $8,932,144,696 of $21,658,941,114 net expense across 2017–2024 (41.24%). This percentage applies only to this expense dataset and its original control rows; it is not a global coverage percentage or an error-rate estimate.

**SC-01 is a provenance defect with $0 numerical error in the confirmed examples.** In 2022 DDN, MPTF's displayed $461,663,168 is the source Total, while its citation names Refunds, transfers and adjustments (the original refund is −$3,737,820). In 2024 MNA, $5,860,258 is likewise the Total, while the refund is −$1,557. Two original table-header/value pairs and the visible source-reference UI establish this. Eighteen destination records (11 DDN, six MNA and one GLA) are flagged by the broader scan; the remaining flags require individual inspection. Do not describe their summed values as misstated money.

Trust-fund charts disclose their positive-area scope and exclusions, unlike the System contributor headline. Regular-budget circular totals for 2025/2026 include the disclosed Peacebuilding Fund portion; honour-roll-based status does not measure partial payments or outstanding balances. The 2025/26 original peacekeeping sample remains blocked by 403 responses and an alternative endpoint returning HTML instead of PDF. All honour-roll dates and 157 fund-to-entity identities remain incompletely independently verified.

## Browser state and deployed-preview boundaries

Fault injection after a successful 2024 load exposes a high-severity state mismatch: when the 2023 data request fails, Organizations and Locations keep their 2024 figures under the 2023 selection. Contributors fails closed instead. Separately, switching Organizations to Funding in 2011/2012 shows a $0 total and no matching entities, even though the revenue dataset is unavailable for those years. Missing data must not be presented as a financial zero. Clear stale figures or preserve an explicit displayed-year label with the error; never present stale values as the requested year.

The fixed local build successfully loaded all 14 default routes and 128 main-slider states with no normal-load JavaScript or data-request errors. Targeted browser checks include metric/funding/grouping switches, selected sidebars, history, mobile layout, and request failures; this is not the Cartesian product of all interactions.

The deployed preview is an older build: 160 of 274 requested JSON files are semantically equal to the workspace, 107 differ, and 7 newer files return 404. Eleven existing routes load; three local Secretariat contributor subroutes are not yet deployed. PAHO and UNINFO attribution problems are reproduced on both versions. The local contributor headline defect must not be claimed as a deployed headline defect: the older deployed chart does not display that headline.

## Methods, confidence and limits

Three subagents reviewed independent domains concurrently, then rotated into contribution schedules, browser behavior, and source-based challenges. The coordinating reviewer maintained baseline hashes, independently recomputed selected findings without importing exporters, visually reread the IRMCT source table, and reproduced PAHO/COD states in the browser. Each domain package preserves checks, notebooks, source responses, table/page images and coverage records.

Passed checks establish specific properties: source-to-export arithmetic, structure, or sampled original cells. They do not certify every source financial statement, identity mapping or interaction combination. Generic ARWO financial-statement references, current-vs-cached geographic revisions, live UNINFO changes, and uninspected original source cells remain explicit gaps. Monetary coverage of manual samples is not claimed as a global percentage across overlapping financial datasets.

The initial static build and TypeScript check passed. The existing Python suite had 37 passes and one taxonomy-metadata failure; the ten citation tests passed. Initial lint reported 15 errors and five warnings. Those checks are validation context, not proof of financial correctness. The taxonomy failure references empty metadata groups; no financial omission was demonstrated from it.

Five source files changed externally during the audit: the Goals page, Functions chart, entity-function details, financing trend chart, and function labels. The original browser build was preserved; an isolated latest-source build passed and received targeted follow-up. Financial datasets remained byte-identical to the recorded baseline. Audit scripts did not modify application or financial data.

## Recommended remediation order

1. Preserve authoritative entity/year/financing totals independently from donor detail; classify missing attribution explicitly.
2. Correct legacy financing mappings and residual/trend category rules; reconcile each category across views.
3. Restore signed financial headlines and access to negative records in every affected chart.
4. Carry UNINFO period and workspace scope into exports and UI; stop presenting shared or unfiltered-period observations as country-year allocations.
5. Repair misleading source/basis statements and source links; add evidenced budget extraction exceptions and retain reconciliation metadata.
6. Resolve contribution-schedule and browser findings, then rerun the saved checks against the corrected build and deployment.

No application or financial data was changed during the audit. Data corrections and deployment remain a separate implementation step; this report supplies their evidence and verification requirements.

## Questions that remain open

- Which authoritative accounting basis should govern the Secretariat Overview, and what explicit bridge reconciles it to consolidated statements?
- What is the exact interval of UNINFO responses without a year filter, and can country allocations be obtained for shared workspaces?
- What source-version history explains the revised geographic download, and which vintage should the portal publish?
- Can accessible original 2025/26 peacekeeping statements and independently timestamped honour-roll snapshots close the remaining verification gaps?

The canonical coverage ledger inventories all 274 files. Manifest checks found every declared default in its year list; two legacy budget-PPB alias files for 2026/2027 are absent, while the current page uses explicit approved/proposed datasets. This is recorded as a compatibility-metadata gap, not a reproduced current-route loading defect.

The audit is complete as a bounded review with recorded failures and gaps. It is not a certification of every original source cell, source identity mapping or browser-state combination.
